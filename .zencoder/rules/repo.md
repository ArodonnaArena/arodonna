# Arodonna ICT Arena — Website Context

## 1. Project Purpose & Vision
- **Why are we building this site?**
  To showcase all the applications and services Arodonna ICT Arena builds. Provide access / demos / links. To communicate credibility (company registration, portfolio), attract clients/customers, offer training, and support.
- **What does success look like?**
  - Visitors can easily view/list all apps/projects.
  - Demos or test versions are reachable.
  - Contact & enquiry flows are clear.
  - Reflect professionalism (registration, training, hardware sales, etc.).
  - Good performance, responsive design.

## 2. Core Identity & Brand
- **Company Name**: Arodonna ICT Arena
- **Founded / Registered**: 19 October 2020 (Benue, Nigeria)
- **Nature of Business**: Sales of computers & accessories; electronics repairs; software utilization training & consultancy.
- **Tone / Voice**: Professional, helpful, innovative, trustworthy.
- **Visual elements & Assets**: Logo / CAC certificate, project thumbnails, consistent colour scheme etc.

## 3. Key Audiences / Users
- Students or trainees interested in ICT training.
- Clients who want software solutions / consultancy.
- People who want to try out your applications or demos.
- Potential business partners.
- Prospective hardware/computer-accessory customers.

## 4. What the Site Must Do (Features / Deliverables)
| Feature | Description |
|---|---|
| Home / Landing Page | Overview of company; mission; highlight key apps/projects. |
| Projects / Portfolio Page | Gallery of applications with thumbnail, name, short description; links to demos and/or repos. |
| Individual Project Detail Page | More details: technology used, images / screenshots, link to demo / test, possibly a “Try now” or “Download / access” link. |
| About / Company Info | Registration info, what you do, your values, possibly team if relevant. |
| Contact Page | Contact form, email, phone, address; possibly map. |
| Blog or Updates | Post news, new app launches, tips, training info (MDX). |
| Responsive Design | Mobile / tablet friendly. |
| SEO Metadata / Social Sharing | Titles, descriptions; OG images. |

## 5. Constraints & Non-Goals
- **Not in scope**: Full e-commerce for now; complex authentication/subscription.
- **Tech Stack**: Next.js 14 (App Router) + TypeScript; Tailwind CSS; shadcn/ui planned.
- **Hosting**: Vercel.

## 6. Success Metrics & KPIs
- Visitors, demo clicks, enquiries via contact form, bounce rate, time on site.

## 7. Milestones & Timeline
1. Context & content gathering.
2. Wireframes / design.
3. Build pages (Home, Projects, About, Contact).
4. Add project demo links / gallery.
5. Testing (UX / responsiveness).
6. Deployment & review.

## 8. Stakeholders & Roles
- Founder/Owner: Provides content, approvals.
- Designer/UI: Layout, visuals, branding (if any).
- Developer(s): Implement frontend + backend bits.
- Content Writer: Text, descriptions, polish.

## 9. Dependencies & Risks
- **Dependencies**: Hosting/domain, demo hosting for apps, up-to-date content & screenshots.
- **Risks**: Delays in demo links; incomplete assets; scope creep; performance issues.

## 10. Style / Aesthetic Guidelines
- Colour scheme (brand colours to be provided).
- Typography.
- Consistent screenshots.
- Clean, minimal, easy to scan.
